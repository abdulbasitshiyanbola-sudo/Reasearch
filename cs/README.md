# Paper-Assisted STEM Problems — Computer Science (CS) Domain

This folder holds the authoring scaffolding for creating **CS-domain** paper-assisted
problems, following *Part 2: Task Creation* of the Trainer Guidelines.

The goal of every task: a problem that is **hard to solve without the source paper**,
**easier with it**, and **self-contained enough that a domain expert could solve it
without the paper at all**.

> [!IMPORTANT]
> **Guideline 1.6.3 — do not submit questions created using AI/LLMs.** The artifacts in
> this folder (template, checklist, taxonomy, sources) are authoring *tools*. The actual
> question you submit must be authored by you, not generated by a model. The file under
> `examples/` is a **format demonstration only** — it is intentionally too easy for a real
> submission and must not be submitted.

## Verifying the golden answers

The numeric golden answers are machine-checkable. From the repo root:

```bash
pip install -r cs/verify/requirements.txt
python3 cs/verify/verify_tasks.py
```

The script independently re-derives each answer (cuckoo 3-core fraction and its (3,1)
fallback, the HyperLogLog bias constant, and the Bloom-filter demo) and asserts agreement,
including external sanity checks (e.g. the published (3,2) cuckoo load threshold and the
HyperLogLog deployed constants `0.673 / 0.697 / 0.709`).

## Authoring workflow (CS)

You can use either workflow from §1.1. For CS, the **alternative workflow** is often
easier: invent a clean, reasoning-heavy problem first, then find a qualifying-licensed
paper whose result/technique makes it easier.

1. **Pick a subdomain** from the taxonomy below (record it on the task).
2. **Draft the problem.** Make it self-contained: state all assumptions, models,
   inputs, constraints, and boundary conditions explicitly. No "in the paper"/"in the
   reference" phrasing.
3. **Solve it fully** and record the full solution and a single, unambiguous golden
   answer (numeric/string/symbolic). Specify rounding (numeric) or canonical form
   (symbolic/string). Keep the answer ≤ 60 characters and not in {`-1`,`0`,`1`,`Yes`,`No`}.
4. **Source a qualifying-licensed paper** (see Licensing) whose key result/lemma/technique
   makes the problem easier — but does not make it a trivial lookup.
5. **Novelty check (A2):** run the novelty check and record the Perplexity results URL.
6. **Pass-rate calibration:** run the 3-run protocol on the Eval Platform and confirm the
   gates in `quality-checklist.md`. Confirm prompt + answer are consistent across run1/run2/run3.

## Proposed CS subdomain taxonomy

> [!NOTE]
> The official taxonomy lives in *A1: Taxonomy*, which is **not included** in the provided
> document. Confirm the canonical subdomain labels against A1 before tagging. The list
> below is a reasonable working set for CS.

- Algorithms & Data Structures (greedy, DP, graph algorithms, amortized analysis)
- Computational Complexity (reductions, hardness, hierarchy theorems)
- Randomized & Streaming Algorithms (sketches, sampling, concentration bounds)
- Approximation & Online Algorithms (competitive ratios, LP rounding)
- Cryptography (provable security, hardness assumptions, protocols)
- Information & Coding Theory (entropy, channel capacity, error-correcting codes)
- Machine Learning Theory (PAC/VC, generalization bounds, optimization rates)
- Distributed Systems & Consensus (fault tolerance thresholds, CAP, quorums)
- Databases & Query Processing (cardinality, indexing, cost models)
- Programming Languages & Type Theory (type soundness, lambda calculus)
- Computer Architecture & Systems (caching, scheduling, performance models)
- Computational Geometry
- Quantum Computing (query/gate complexity, algorithm analysis)

## Source paper licensing (§1.3)

The paper **must** be published under one of: **Apache, MIT, CC BY, CC BY-SA, CC0, BSD**.

CS-friendly venues that commonly use qualifying licenses (verify per paper):

- **arXiv** (`cs.*` categories) — license is set **per paper**; look for CC BY 4.0 /
  CC BY-SA / CC0 in the submission's license field. Many `arXiv` papers are *not* CC; check.
- **JMLR** (Journal of Machine Learning Research) — CC BY.
- **TMLR** (Transactions on Machine Learning Research) — CC BY 4.0.
- **LIPIcs** (Dagstuhl; e.g., ITCS, ICALP, ESA, CCC, FSTTCS, APPROX/RANDOM) — CC BY.
- **PLOS Computational Biology** — CC BY (for CS-adjacent / computational work).
- Open textbooks/monographs under a qualifying license.

> Do **not** assume a venue's license; confirm the specific paper's license string.

## Uniqueness (§1.6)

- Prefer using each paper once; **max 3 uses** of the same paper.
- Each submitted problem must be distinct (duplicate check is built into submission).
- Do not reuse questions from any source, and do not generate questions with AI/LLMs.
